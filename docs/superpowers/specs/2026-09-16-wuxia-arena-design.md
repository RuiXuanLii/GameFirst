# GameFirst：2D 俯视角武侠首版设计

日期：2026-09-16

状态：用户已选择 2D 俯视角武侠，并授权修改 RuiXuanLii/GameFirst。本文将该方向细化为可审阅的首版规格；下列操作、数值和敌人配置为建议默认值，等待用户审阅。游戏实现尚未开始。

## 1. 目标与边界

交付一个可在 Windows 运行的单人小关卡。玩家进入练武场，利用移动、挥剑、闪避连续击败三波敌人；清场后胜利，生命耗尽后失败，两种结局均能重新开始。

第一版包含一个角色、一张封闭地图、两类敌人和三波战斗。不包含联网、开放世界、背包、装备、任务树或长期存档。先验证战斗是否有趣，再扩展内容。

## 2. 已有工程

- `project.godot`：Godot 4.7 项目，已配置 WASD；未指定主场景。
- `main.tscn`：Node2D 场景，含角色、摄像机和一面墙。
- `player.gd`：CharacterBody2D 四方向移动，速度 250。
- 已发现本机 Godot 4.7.2 可执行文件。
- 现有文件先完整保存为原型基线，不将其描述为已经验证的游戏版本。

## 3. 操作与战斗规则

- WASD 移动，鼠标位置决定面向，左键挥剑，空格闪避，Esc 暂停。
- 挥剑使用前方扇形近战范围；每次攻击对同一敌人最多造成一次伤害。
- 初始建议：玩家生命 100，攻击伤害 25，攻击冷却 0.35 秒。
- 闪避持续 0.18 秒，冷却 0.8 秒；闪避期间免疫伤害且无法挥剑，仍受场地墙体约束。
- 普通受伤后无敌 0.5 秒，避免同帧多重接触瞬间清空生命。
- 死亡立即停止移动、攻击与受伤处理，只触发一次失败结算。
- 暂停冻结战斗与计时；恢复不会产生补发攻击。

上述数值集中到可调参数中，试玩后可调整而不改动核心流程。

## 4. 敌人、波次与胜负

- 刀客：生命 50，近距离追击，攻击前给予清晰预警，命中伤害 10。
- 重装刀客：生命 100，移动较慢，攻击前摇更长，命中伤害 20。
- 第一波 3 名刀客；第二波 4 名刀客和 1 名重装刀客；第三波 5 名刀客和 2 名重装刀客。
- 只有当前波敌人全部死亡才允许推进波次；敌人死亡通知不得重复计数。
- 波次间留出 2 秒提示并恢复玩家 20 点生命，不超过上限。
- 最后一波清空后胜利；若同帧发生玩家死亡和敌人清空，失败优先。
- 重开时生命、敌人、波次、计时器、攻击命中记录和界面全部复位。

## 5. 场景与视觉

采用清晰可读的 2D 像素风。原型先使用简单占位形状和颜色，跑通战斗后替换人物、地面、围墙和剑光素材。

默认设计分辨率 960×540，验收同时检查 1280×720。封闭练武场内暂不放复杂障碍，保持追击路径可预测。界面显示生命、当前波次及闪避冷却；开始、暂停、胜利和失败均有明确按钮及键盘焦点。

敌人预警不能只依靠颜色，需有姿态或范围提示。受击加入短促闪烁、击退、音效及轻微屏幕震动。所有外部素材记录来源与使用许可。

## 6. 结构与职责

沿用现有 `main.tscn` 作为组装入口，逐步提取可复用角色场景，不在初始化阶段重写整个工程。

- `features/player/`：玩家场景、输入、面向及闪避。
- `features/combat/`：生命、受伤入口、攻击范围、单次命中去重。
- `features/enemies/`：敌人场景与待机、追击、攻击、受伤、死亡状态。
- `features/arena/`：围墙、出生点、波次及对局状态。
- `ui/`：开始、HUD、暂停和结算；通过信号读取战斗状态。
- `assets/`：图像、字体、音效及来源记录。
- `tests/`：伤害、攻击去重、波次、重开等关键规则验证。

生命组件独立拥有生命状态，暴露统一受伤方法并发出生命变化和死亡信号。波次控制器只负责生成敌人与统计存活数量。对局控制器决定开始、暂停、胜负及重开，不承担角色输入和战斗细节。优先使用局部节点和类型明确的信号，不引入庞大的全局管理器或额外框架。

## 8. 验证方法

对关键规则先验证失败案例再实现：重复命中、闪避免伤、死亡只通知一次、波次完成只推进一次、同帧胜负及完整重开。

每阶段执行 Godot 脚本/资源加载检查及运行检查，读取错误和警告；有界面变动时检查两个分辨率下的布局。实际操作验证移动、挥剑、闪避、受伤、暂停和结算，不能仅以启动成功替代玩法验证。未能完成的验证写入进度记录。

导出前核对本机版本及对应导出模板，使用真实生成的 Windows 构建再试玩，不将编辑器运行当作导出成功。
